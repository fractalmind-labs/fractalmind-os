# OKR

This repo uses `HEARTBEAT.md` to drive coordination. OKRs define **what** we want to achieve; the heartbeat drives **how** we get there.

## Format

Each OKR has a title and 2-4 Key Results (KRs). KR status progresses: `PENDING` → `IN PROGRESS` → `COMPLETE`.

```markdown
### OKR: <objective title>

- KR1: <measurable key result> — `PENDING` (owner: <agent-name>)
- KR2: <measurable key result> — `IN PROGRESS` (owner: <agent-name>)
- KR3: <measurable key result> — `COMPLETE` (owner: <agent-name>)
  - <evidence or link>
```

**Rules:**
- Keep OKRs actionable and scoped (days, not months).
- Each KR should be independently verifiable (link to PR, issue, or test output).
- Move completed OKRs to the ARCHIVED section to keep the ACTIVE section focused.
- When the ACTIVE section is empty, the heartbeat replies `HEARTBEAT_OK`.
