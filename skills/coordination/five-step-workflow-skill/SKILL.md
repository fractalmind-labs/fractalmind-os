# Five-Step Workflow

Use this as a two-layer method:
1. first-principles thinking to define the right problem
2. five-step workflow optimization to design the right execution path

## Inputs to collect

Capture these if available:
- goal
- current workflow or process steps
- constraints: time, compliance, safety, quality, budget, physics, technical limits
- bottlenecks, delays, handoffs, repeated waste, or inherited assumptions
- what the user wants optimized: cost, speed, quality, focus, reliability, or scale

If details are missing, make the smallest reasonable assumptions and label them.

## Layer 1: first-principles thinking

Use this layer to avoid optimizing the wrong thing.

Ask:
- What is the real objective?
- What problem are we actually trying to solve?
- Which assumptions are facts, and which are conventions?
- What are the hard constraints?
- If we started from scratch, how would we design this?

Output from this layer:
- the true objective
- the essential constraints
- the non-essential assumptions to challenge
- a reframed version of the problem

## Layer 2: five-step workflow optimization

After the problem is reframed, apply the five steps in this exact order. Do not jump to automation first.

### 1. Question every requirement

Ask of each requirement, approval, report, meeting, rule, or feature:
- Is this actually necessary?
- Who asked for it?
- What problem does it solve?
- What breaks if we remove it?

Mark each item as:
- keep
- unclear
- likely removable

### 2. Delete aggressively

Remove steps, approvals, reports, tools, fields, meetings, or handoffs that do not clearly earn their cost.

Heuristics:
- remove duplicate review layers
- remove status work that exists only to feed another process
- remove manual copying between tools
- remove "we've always done it this way" steps

### 3. Simplify and optimize what remains

After deletion, redesign the remaining flow to be simpler.

Common moves:
- reduce handoffs
- merge adjacent steps
- shorten approval chains
- standardize templates or checklists
- move decisions closer to the operator
- make inputs and outputs explicit

### 4. Increase cycle speed

Only after the process is worth keeping, shorten turnaround time.

Examples:
- smaller batch size
- faster review cadence
- parallelize independent work
- tighter feedback loops
- shorter meeting length or async-first updates

### 5. Automate last

Automate only stable, repeated, clearly valuable steps.

Good automation targets:
- data entry
- reminders and routing
- report generation
- repetitive QA checks
- formatting and summarization

Avoid automating confusion or waste.

Use this structure unless the user asks for another one:

- true objective:
- hard constraints:
- assumptions to challenge:
- from-scratch view:

### Current workflow
- step 1
- step 2
- step 3

### Five-step diagnosis
1. Questioned requirements:
   - ...
2. Deleted:
   - ...
3. Simplified:
   - ...
4. Sped up:
   - ...
5. Automated last:
   - ...

### Optimized workflow
- new step 1
- new step 2
- new step 3

### Expected gains
- time
- cost
- quality
- clarity

### Risks and guardrails
- compliance or safety boundaries
- what should stay manual
- what to validate before rollout

## Response style

Prefer concrete recommendations over theory.

When useful, end with one of these:
- a one-page SOP version
- a manager version
- an operator checklist
- a Notion, spreadsheet, or automation-ready version
