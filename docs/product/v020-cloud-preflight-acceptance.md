# v0.2.0：真实云 Host 的有限执行与独立验收

基线 `8fa6b61`。复用[前次云审阅停止结算](v020-cloud-review-stop.md)的 Ubuntu Host、系统凭据库、成员、原 Android 安装版身份、组织及 localnet。**同一原 OKR 已完成两个云 KR 和独立最终验收**；完整 v0.2.0 仍按 [#40](https://github.com/fractalmind-labs/fractalmind-os/issues/40) 验收。

## 修复内容

- 执行预检先校验当前权限，再读取受保护结果钥；预检失败不占用命令。调用内已解析的类型及全部依赖版本在 Inspect／Reserve 前重新批量读取，链上开始交易仍原子校验权限。
- 对已知 Run 直接重新读取 Run／Capability，核对原始绑定、类型、UID、版本和预算，减少重复查找索引。读取来源保存在私有字段中，不能从 JSON 重建成执行权限；当前 attempt、cursor 和停止标记仍单独校验。
- 交接第一次完整来源校验后，物理排他阶段重新读取全部依赖版本和 Sui Clock。证明绑定精确命令、提案、Run 和 attempt，仅用于这一次审阅，不能延长租约或授权工具。
- Host 结果 Gas 与结果钥的独立预检并发读取，等待两者完成后才能预留；密钥失败仍保留原错误优先级。结果和开始确认使用原 Run 的新读取，未知交易仍只查询原摘要。
- 区分权限快照被并发写入改变与撤权：心跳的未验证帧被丢弃，连接保留，下一次发送重新校验；已收到的消息仅重新读取权限一次，通过后才分发原消息。真实撤权、过期、网络不可确认或第二次失败仍阻止分发，不重送命令或刷新签名期限。

本次生产修改仅涉及 envd Go 源码。App、SDK、Move 和 Rust 没有修改；测试使用当前正式 App 控制器及原 APK 的实际 Keystore IPC。

## 保留的失败与修复过程

- r4 的完整重复交接读取超过原物理审阅期限，失败回执零预算结算。
- r5 的允许路径 `docs` 尚未存在，审阅拒绝创建目录。操作员只准备空目录，没有替 Agent 写目标文件。
- r6 的 Host 接受证明在期限内签名，但密文结果上链后已过期；App 拒绝批准，未推进 KR。
- r7 心跳快照竞争关闭连接，原审阅未开始。明确停止同一原 Run，链上 CANCELLED／零预算，无伪造 Host 结果。
- r8 首个工具 Run 在夹具等待结束后成功，随后 5 分钟测量过期；只读恢复与拒绝检查均保留。
- 私有恢复脚本的 helper 提取出现语法错误，在执行前失败，没有 IPC／费用／交易。其后两个夹具断言分别把“最大 3 次预算”误认为实际消耗，并在 KR 游标已推进后期待导航仍返回历史 Run。原链上成功和 Human 确认均保留，修正断言后从原报告继续，没有重复授权、派发或验收。
- 一次 SSH 升级连接中断，经只读核对确认旧二进制仍在后继续；一项 WebSocket 回归夹具遗漏测试 Host signer，修正后最终回归通过。

## 回归与证明范围

Go `nodecommand`／`runtimeadapter`／`sui`／`ws`／`cmd/envd` 五包 race 与 Linux AMD64 构建通过。覆盖预检后撤权／依赖改变、过期、未知 RPC、JSON 丢失私有读取来源、结果钥绑定、停止标记以及真实 WebSocket 竞争／撤权／单次消息分发。最终日志部分复用本增量先前成功缓存；没有把 App／SDK／Move／Rust 计作全量重跑。

本次是实际云 envd＋本地 Sui／Coordinator 的 SSH 回环连接，云模型关闭，采用有边界的原生文件任务。Android 为任务模拟器，费用与独立 Human 决策由脚本显式执行。APK 没有重新打包，新停止 UI、可见安装版全链路、实体手机、公共 testnet 和 Host OS 重启仍未验收。临时 Secret Service／反向隧道不等同于生产自启动配置。

新审阅在原 55 秒物理期限内完成，但独立批准确认时仅剩约 **4.1 秒**。这证明自动脚本链路通过，仍需验证并改善可见 UI 下的人工审阅时间；不能据此宣称跨公网的人工交接体验已完成。Mac mini 本机 Keychain 授权及完整 [#40 验收](fractalmind-app-v020-validation.md)保持未完成。
