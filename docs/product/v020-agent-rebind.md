# v0.2.0：已有实例显式重新关联

依据 PRD v0.11 J11／FR-39 与 `fractalmind-app-prototype-v2`。在[仅观察导入](v020-agent-import.md)后，已有记录撤销、Host 成员资格更新或工作区变化需要再次核对。本增量实现仅观察记录的显式重新关联；完整 v0.2.0 未完成。

## App 流程

1. 从 Host 签名的有效发现结果选择实例，读取该组织／Host／实例的精确链上登记。
2. 核对原记录 ID、逻辑版本、成员资格、工作区指纹、撤销状态和运行时，并与新发现的 Host／工作区比较。
3. 明确选择“重新关联为仅观察”，确认后读取当前管理／读取权限、成员指针及独立 Host 签名扫描，再报价。正常且已经一致的记录返回原登记，不重复付款。
4. 显式确认费用。提交前和原生签名返回后再次核对已审阅记录、权限、源扫描及报价。链上版本条件同时防止最后一次检查之后发生的并发变更。
5. 成功保留原记录 ID 和实例 ID，更新成员／工作区，推进逻辑版本并使旧能力版本失效。列表显示完整记录 ID 和最新 `vN`。登记不证明当前进程在线。
6. “恢复登记交易”按原操作类别及摘要查询。未知结果不能开始新操作；恢复后确认未提交或已知结果，再重置并核对新选择。

原记录、工作区和 Host 快照只保留在页面内存。技术尝试增加 `kind=import|rebind` 用于区分交易 journal 的请求前缀，旧的导入尝试仍可读取；不缓存实例或业务关系。

## 合约与控制边界

- 新增 `host::rebind_agent_at_version`，条件为已审阅 `ManagedAgent.version`，不匹配以 `E_VERSION=9208` 拒绝。既有对象字段、事件和原 `rebind_agent` 签名保持不变。
- SDK 的 `rebindAgent({expectedVersion, ...})` 使用新接口；不传版本保持已有调用。生产 App 始终传已审阅版本，不能降级调用旧接口。目标部署须包含此新增函数；本次仅发布隔离 localnet 包，没有升级公开网络部署。
- 旧记录必须属于所选 Host／实例并为 `tmux-observe`、`control_confirmed=false`。曾确认可控运行时的记录要求独立安全交接，不能在此流程直接降级或改为可控。
- 重新关联不启动、停止或重启进程，不恢复旧能力，不自动纳入 OKR，不自动继续执行。新成员资格仍需通过链上目录与签名扫描核验。
- 已审阅记录在控制器中复制并冻结。报价、提交及原生签名返回后核对当前记录，防止外部修改预览对象改变授权内容。

## 验证证据

- [控制器与构建](evidence/v020-agent-rebind-unit.json)：App **87/87**、SDK **105/105**、Move **121/121**，App／SDK 类型与构建及链脚本类型通过。覆盖确认、记录变化、来源丢失／过期、设备权限变化、原摘要恢复、回执逻辑版本、原生签名等待期间的变化，以及禁止跳过可控实例交接。
- Host 更换成员和工作区的来源选择有控制器测试。本增量之后，[Host 重新接入专项验收](v020-host-rejoin.md)验证了同一 worker、Host 密钥和真实 tmux 进程经新成员资格认证，再由 App 显式重新关联；正式 OS 存储、进程重启和安装后 UI 仍未验收。
- [实际链报告](evidence/v020-agent-rebind-localnet.json)：**19 项检查、16 笔成功交易、1 笔预期失败交易**。真实 tmux／内核实例经 Go Host 签名，App 撤销后的显式重新关联保留记录并推进版本；响应丢失后只查原摘要，重新关联广播一次。另一个确认的重新关联使旧 App 报价拒绝提交。
- 为直接证明合约竞态拒绝，负向夹具先在旧版本有效时构建交易，再由另一操作推进版本，然后广播旧版本交易。它使用独立生成的测试 Gas 付款者，避免并发夹具消费原 Gas；这不改变生产 App 的设备自付模式。实际 Move 失败 `9208`，获胜记录保持版本 5，未重复创建实例或授予控制。
- [实际浏览器记录](evidence/v020-agent-rebind-browser.json)从同一报告的真实链读取同一实例／记录和最新版本 5，中英文及明暗展示，网页授权按钮禁用。没有注入假实例。安装后对话框、OS 密钥库及持久 journal 重启未验收。

调试负向用例时，早期独立夹具有一个原摘要查询仍为未知，见[保留的技术记录](evidence/v020-agent-rebind-prior-unknown.json)。该摘要未重发、未替换为新尝试；后续测试使用不同的组织、Host、记录和测试钥。通过报告不能证明旧未知交易已经失败或完成。

本次没有改变 Go 运行时，复用此前验收的发现辅助二进制与签名逻辑；链验收注入测试设备钥和 App 内存 journal，不能替代安装后原生 UI 流程。

## 重现与剩余范围

已有运行中的本地链／faucet、包含新版本条件接口的隔离部署及此前构建的 Go 发现辅助程序后，在 `apps/fractalmind-app` 执行，报告必须使用新路径：

```sh
FM_ENVD_JOIN_CLI_BIN=/tmp/fm-envd-agent-discovery-tests \
FM_ENVD_CHAIN_CONNECTION=1 FM_ENVD_AGENT_DISCOVERY=1 \
FM_ENVD_AGENT_IMPORT=1 FM_ENVD_AGENT_REBIND=1 \
node --import tsx scripts/host-admission-localnet.ts DEPLOYMENT.json NEW_REPORT.json
```

仍需实现受约束适配器的接管、旧执行停止／检查点、ACTIVE OKR 授权与明确继续、直接对话／介入及自主验证闭环。Host 重新加入的实际链协议流程见上述专项验收；正式密钥库与重启、云 TLS Host、五平台安装运行和完整身份旅程保持未验收。原生 App 仍等待用户处理系统密钥库授权。完整目标范围不变。
