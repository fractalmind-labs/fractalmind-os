# v0.2.0 App：OKR 暂停、调整与审阅后恢复

依据 #27/#28/#34/#45、PRD v0.11 与原型 v2。基线 `d2db282`。
本增量补齐正式控制器及工作台／OKR 详情入口。完整 #40 尚未完成。

## 交互与持久状态

- 「暂停与调整」读取当前目标、规格、原 Run 和预算。公开网页提示解锁原生设备，不能签名或读取私有规格。
- 暂停原因加密上链，保存原约定指针；使旧执行约定失效。暂停不清空在途预留，也不表示已经开始的工具停止完成。
- 停止请求绑定原 Run。排队取消可立即结算；运行中须等待 Host 停止确认及原账本结算。结果未知时只查询原请求，不自动重发。
- 草稿／暂停目标可修改完整规格。尚有未结执行或预留时禁止修改；新上限不得低于累计实际支出。换版重置 KR 测量、验证与游标，保留链上原执行历史及实际支出。
- 暂停后重新选择实例、审阅新约定、确认 Host 的新签名并分别批准。批准不会创建或投递执行；之后明确继续才执行。
- 每笔介入操作分别报价、确认及原生签名。关闭、页面隐藏和设备到期时释放私有内容及报价。客户端持久保存公开请求定位与技术 journal，产品状态仍在 Sui。

## 历史证据与新执行资格

暂停后保持同一规格而重新审批，可保留已验证 KR。最终验收读取原不可变 Run、预算结算、测量及独立 Human 验证记录，再按当前已批准计划核对具体文件及内容哈希。

旧结果的执行约定版本与当前人审约定版本分别记录／展示。旧结果可成为独立人审的证据；执行资格仍要求当前约定和政策。新的规格换版会清除当前 KR 验证，不将旧规格的成果直接算入新目标。

## 已验证范围

[R2 实际联测](evidence/v020-okr-intervention-localnet.json)：**13 项检查、25 笔 App 确认交易**。实际 OS 密钥库、正式原生控制器、设备 HTTP Coordinator 和生产 envd 跑通：

1. 草稿的加密规格换版，未创建 Run 或投递。
2. 第一个 KR 执行、结算及独立验证。
3. 第二个原 Run 排队后暂停，预留仍为 3；旧继续拒绝。
4. 仅取消该原 Run 后预留归零，已用仍为 3。
5. 新 Host 审阅和独立人批准，保留第一 KR；没有隐式投递。
6. 新 Run 明确继续第二 KR、分别验证及最终验收；ACHIEVED、游标 2、已用 6／预留 0。
7. Host 撤销后路由拒绝，原历史仍可读取，OS 测试凭据清理确认。

[R1 原报告](evidence/v020-okr-intervention-prior.json)保留另一轮完整恢复成功：12 项检查、24 笔确认交易，不包含草稿换版。没有重放两轮原请求。

[回归](evidence/v020-okr-intervention-unit.json)：App **178/178**、构建及脚本严格类型通过。新增检查覆盖未结执行／累计支出、签名前后版本变化、停止原 Run、未知原请求优先及历史证据版本。[真实浏览器](evidence/v020-okr-intervention-browser.json)核对中文白天工作台和英文黑夜 OKR 详情入口及网页保护。
