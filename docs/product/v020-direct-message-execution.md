# v0.2.0 直接消息执行与原生结果回执

依据 PRD v0.11、原型 v2、#41/#43/#45。本增量在 `c907433` 的来源读取基础上接通真实直接消息执行。完整 #40 目标仍未完成。

## 实现

- 签名命令验证器在预留之前核验 direct 来源；每次文件工具操作重新核验当前权限、原消息、原 Run、Host 开始所有权、停止状态、期限和工作区。
- 生产 envd 使用独立 direct-agent 扩展的普通／单次批准 begin 和 finish 入口，结果正文复用 core 加密记录。当前资格变化不改写原历史身份；未知开始或结算回执继续保留原请求及预算，不重新派发。
- 原生文件适配器固定实际实例及工作区 inode，与 OKR 运行和约束审阅共享物理占用。`file.write` 执行明确的有限文件任务，`file.read` 只获得读取工具，`status` 不消耗工具预算并可查询忙碌实例。
- `ask` 明确返回不支持；通用模型对话尚未接入。有限文件任务不能作为通用对话或自主规划的验收证据。
- App 领域层和 Coordinator 使用独立 direct scope、当前 operate 权限及设备签名。原生结果控制器封装 Host 结果密钥；SDK 在创建交易之前检查常驻动作、边界、单消息上限及剩余额度，超限需要精确单次审批。
- Go PTB 编码复用同一对象 ID 的输入。执行与批准设备相同时，两处 Grant 参数引用同一个对象输入；纯地址值不参与对象去重。

[完整原回执](evidence/v020-direct-message-localnet.json)记录隔离 localnet 上实际 OS 密钥库、设备 HTTP Coordinator 和生产 envd 的 **14 项检查、41 笔 App 确认交易**。

| 场景                                     | 结果                                                |
| ---------------------------------------- | --------------------------------------------------- |
| 两个 KR 按序执行、分别验证、独立最终验收 | OKR 达成；工具预算已用 6、预留 0                    |
| 普通常驻文件写入                         | 实际生成文件；已用 3                                |
| 定向文件读取                             | 实际读回同一成果；已用 1                            |
| 状态消息                                 | 返回原生实例状态；工具预算 0                        |
| 完全重复投递                             | 返回原 Run／不可变结果，无新增工具支出              |
| 普通请求超过单消息上限                   | SDK 在交易构造前拒绝                                |
| 精确单次批准 5 次工具调用                | 实际已用 3、释放剩余 2；审批预算预留归零            |

最终常驻预算已用 **4**、预留 **0**，单次审批已用 **3**、预留 **0**；既有 OKR 预算仍为 **6**、预留 **0**。这些数值是工具调用次数，不是 SUI 金额。测试 OS 凭据清理已确认，报告不包含私钥或恢复码。

[回归摘要](evidence/v020-direct-message-unit.json)：SDK **138/138**、App **147/147**、两者构建、联测脚本严格类型检查，以及 envd 六个相关包 race 通过。新增覆盖来源 hook、工具边界、停止、实例占用、工作区替换、零预算查询、普通／批准交易路由和重复对象输入。此次没有修改 Move 或 Rust，也没有重跑此前的 Move／Rust 门禁。

## 前序尝试及原账本

[前序只读复查](evidence/v020-direct-message-prior.json)保留 R8–R13 的原准备回执、Run 和预算，**0 次广播、无原请求重放**。

- R8 在投递前使用了过时的接收资格快照；R9–R11 的执行已成功，失败源于测试错误要求原 claim allowance 清零。完成依据应为 claim 已结算及累计预留释放，原 allowance 保留。
- R12 暴露 SDK 缺少普通单消息额度预检；R13 暴露同一批准／执行 Grant 在 PTB 中重复输入。两项修复后，新隔离 R14 完整通过。
- R8 原普通 Run 和 R13 原批准 Run 仍为 QUEUED，分别保留普通预留 3、批准预留 5。新联测成功不等于这些历史预留已取消；报告没有将它们标为已释放或已清理。

## 完整验收的剩余范围

该联测通过脚本明确作出 Human 决定，OS 桥为隔离子进程，Host 密钥与技术 journal 使用内存提供器，Coordinator 为同机 loopback。它不证明安装后的用户界面、持久 IPC／journal、云 TLS Host、手机核心旅程或清缓存重启恢复。

正式 App 对话、常驻权限及审批／介入界面、通用对话适配器、首次直接安全纳管、持续自主顺序 KR、暂停调整后恢复、技能投影，以及 main 旧包／对象真实升级仍须完成。当前直接消息依赖已通过 OKR 审阅获得控制能力的受管理实例；不能将其称为首次直接纳管。#43/#45 和完整 v0.2.0 保持未完成。
