# FractalMind App 交互原型 v2

基于 [产品 PRD v0.10](../fractalmind-app-prd.md) 的第二版交互原型。[v1 原型](../fractalmind-app-prototype/README.md)
保持不变，两者可以并排评审。所有数据、交易、执行、测量与验证都是演示：不连接真实主机、
不提交 Sui 交易、不调用模型，也不会发出任何网络请求。

## 运行

在仓库根目录执行：

```sh
python3 -m http.server 4181 --bind 127.0.0.1 --directory docs/product
```

打开 <http://127.0.0.1:4181/fractalmind-app-prototype-v2/>。也可以直接用浏览器打开 `index.html`
（`file:` 下的本地存储行为取决于浏览器）。无需安装依赖，没有构建步骤。

评审入口参数：

| 参数 | 作用 |
| --- | --- |
| `?view=hosts` | 打开指定页面（`workbench`、`okrs`、`okrs/new`、`hosts`、`agents`、`memory`、`governance`、`identity`、`settings/fees`、`orgs`、`network` 等） |
| `?journey=J7` | 直接开始某个 PRD 旅程走查（`NAV`、`J1`–`J11`） |
| `?device=phone` | 手机预览框 |
| `?lang=en`、`?theme=dark` | 语言与外观 |
| `?reset=1` | 重置演示数据（不影响语言与外观偏好） |

## v2 改了什么

v1 对 PRD 的覆盖非常全面；v2 保留同样的产品模型，重点改进“评审时能不能一眼看懂、能不能持续迭代”。

| v1 中观察到的问题 | v2 的做法 |
| --- | --- |
| 工作台最先展示地图和大量指标，“需要你决定”的事项在页面底部 | **决定优先**：工作台第一屏是“需要你决定”——越界请求、KR 验收、未知副作用确认、设备配对，每张卡片带原因、影响范围、预算影响、替代方案和有效期，可就地处理；没有待办时明确告诉你“Agent 在授权范围内继续推进” |
| “Agent 声明 / 采样测量 / 已验证 / 已验收”在各处表达不一 | **可信阶梯**：统一的四级标记贯穿 KR、证据、足迹和地图检查点；过期数据单独标“待更新”，不会被当成 0% 或完成 |
| 当前组织、执行设备、运行时和权限散落在页面各处 | **常驻上下文栏**（PRD 原则 4）：工作区 › 执行主机 › Agent 与模型 › 本设备权限，始终在顶部；切换组织、改派主机后随之更新 |
| 演示控件（注入场景、模拟 heartbeat）与产品按钮混在一起 | **评审工具独立**：右下角“评审”（⌘.）集中放 heartbeat、自动推进、路况注入、故障注入、设备视角、手机预览和数据重置；产品界面只保留产品本身的操作 |
| 评审者需要自己拼出 PRD 旅程 | **PRD 旅程走查**：评审工具按 J1–J11 和“运行导航”列出步骤，完成的步骤会自动勾选 |
| 手机是桌面页面缩进手机框 | **手机单独设计**：工作台先显示决定事项，地图换成路线条，5 个底部入口 + “全部功能”，对话与对话框改为底部抽屉 |
| 每条流程各自模拟链上确认 | **统一的交易状态**：所有链上写入都经过同一套“待确认 → 已确认 / 失败 / 结果未知（查询原交易，不重放）”，并按结果记录运行费 |
| 分形、逐级组合的组织模型没有直观呈现 | **成长路径**：“我的组织”展示个人组织 → 团队 → 子组织 → 联邦，后续阶段只显示说明，不提供不可用的操作 |
| 单文件 567 KB，测试需要用正则从 HTML 中抽取脚本 | **可维护的结构**：领域模型是纯函数，`verify.cjs` 直接 `require`；页面按领域拆分，普通脚本即可在 `file:` 下运行 |

## 视觉语言

视觉围绕使命与价值观设计：

- **开放、可验证**：中性墨色文字配干净的白色界面，像公共基础设施，而不是品牌商品。颜色只用来表达事实：已验证（绿）、当前进度（蓝）、边界与偏航（琥珀）、阻断（红）、等待依赖（青）。
- **智能**：鸢尾紫（iris）是操作、选中状态和最高可信级别“已验收”的强调色。
- **分形**：青 → 鸢尾 → 紫的渐变只用于身份元素——递归方块标志、Human 头像和欢迎页主视觉。欢迎页直接写出使命：通过分形、自相似的 Agent 组织，走向一个没有人能独占的 ASI。
- 浅色与深色共用同一套语义令牌。浅色主题使用中性白；PRD §8.2.1 目前写的是“暖白背景”，若采纳这个方向，需要同步更新 PRD。

## 评审方式

点右下角 **评审**（或 ⌘. / Ctrl+.）打开评审工具。桌面端首次访问会自动打开一次。

- **按 PRD 旅程走查**：选择一个旅程，页面跳到起点，右下角出现步骤清单，完成后自动勾选。
  - `NAV` 运行导航：推进 heartbeat → KR2 达标并由预授权验证者验证 → 验收 KR1 → KR3 触及边界 → 拒绝外部请求后切换本地路线 B → 注入偏航并纠偏 → 验收 KR3 与最终结果 → OKR 达成并写入记忆。
  - `J1` 安装到首个成果、`J2` 手机接手、`J3` 取消与恢复、`J4` 权限与设备、`J5` 更大协作、`J6` 导出与更新、`J7` 邀请码接入主机、`J8` 另一台设备、`J9` 单恢复码、`J10` 运行费、`J11` 发现并导入 Agent。
- **运行模拟**：推进一次 heartbeat、自动推进（遇到需要你决定时自动停止）、重连补发上一个 heartbeat（验证去重）。
- **注入路况**：正常推进、临近边界、目标偏航、疑似空转、路径阻断、等待依赖、失去观测。注入的是带“评审注入”标记的演示观测，产品界面按同样的约定处理。
- **故障注入**：下一笔交易失败、Sui RPC 不可用（结果未知 → 查询原交易）、Coordinator 不可达（已入组但等待连接、命令无回执）、开放网络查询失败、赞助方离线、执行主机失联。
- **设备视角**：MacBook（管理设备）、iPhone（可执行与审批）、Pixel（只读、数据待同步）。视口大小从不授予权限。
- **视图与数据**：手机预览、导出演示状态、退出此设备（回到欢迎页）、载入演示身份、重置演示。

演示身份的恢复码是 `FMR1-T-DEM0A-DA000-RECVR-Y2026-7`（仅用于本原型）。在恢复页打开评审工具可以一键填入；
用过一次后需要重置演示才能再次使用。本次会话生成的新恢复码也可以使用。

## 关键规则（与 `js/model.js` 对应）

- **达成度**：`clamp((current − baseline) / (target − baseline), 0, 1)`，提升与降低型指标通用；总体按正权重归一化加权；缺失或过期数据标为未知，不当作 0% 或完成。
- **完成独立于进度**：100% 还需要已验证证据、通过验证、依赖完成；需要人工验收的 KR 在验收前不算完成；全部 KR 完成后复核成功标准，最终验收后才是 ACHIEVED。
- **ACTIVE 上限 3**：第 4 个进入候选池；激活前检查工作区、Agent 部署、主机与授权（FR-40）；重复提交不重复激活。
- **路况**：正常推进、临近/触及边界、目标偏航、疑似空转、当前路径阻断、正常等待依赖、状态未知；方向与权限分别展示（可以“偏航但仍在授权内”）。
- **审批**：待处理、已同意、已拒绝、已过期、已失效。已同意 ≠ 已执行，执行结果关联回审批；约定版本变化会让绑定旧版本的待处理审批失效；提交时重新校验。
- **Run**：排队、运行、待审批、恢复中、需要确认、成功、失败、已取消。取消先显示“正在停止”，执行设备确认后才是“已取消”；重试是新的 Run，保留旧记录与副作用。
- **邀请码**：管理员签名一次，新主机输入一次；兑换在一笔交易内完成消费、入组与 7 天执行授权；兑换证明绑定设备，复制的证明无效；并发兑换只成功一笔；失败不消费；链上成功但连接失败时保留资格并重试连接。
- **设备与身份**：可用操作 = 组织角色 × 设备授权 × 数据访问；新设备默认当前组织 7 天只读；授权与数据同步分开；锁定只保护本机凭据。
- **恢复码**：带版本、网络与校验位；查找只定位身份，不授予权限；恢复在一笔交易里撤销旧设备、授权新设备并消费恢复码；交易里只带摘要，不带原始恢复码。

## 数据与限制

- 状态保存在本地存储 `fractalmind.prototype-v2.state`，偏好保存在 `fractalmind.prototype-v2.prefs`；与 v1 的存储互不影响。多个窗口会同步到最新状态，旧窗口不会覆盖新写入。
- 邀请码和恢复码只保存在页面内存中：刷新后无法再次显示邀请码（链上只保留验证公钥），普通导出不含任何凭据。
- 摘要使用演示用的 FNV 哈希，兑换证明与恢复码格式只是交互示意，不是生产协议或安全边界；浏览器开发工具可以修改任何状态。
- 相比 v1 简化或未覆盖：真实 WebCrypto 签名演示、无邀请码时的人工审核流程（只保留说明）、独立的评审档案存储、远程桌面只提供示意画面。
- 原型不能替代 PRD §8.4–8.5 列出的合约、运行时、加密与五平台原生验收。

## 文件结构

```text
index.html            入口（预先应用主题，避免深色闪白）
styles.css            设计令牌（浅色/深色）、布局与组件
js/model.js           领域模型：纯函数，无 DOM
js/fixtures.js        双语演示数据（相对于首次载入时间）
js/core.js            状态、偏好、国际化、路由、渲染、交易模拟
js/shell.js           侧栏、上下文栏、手机导航、命令面板（⌘K）、通知、锁屏
js/view-*.js          各页面
js/review.js          评审工具与 PRD 旅程走查
js/main.js            启动与评审入口参数
verify.cjs            领域模型与演示数据的回归检查
```

## 回归检查

```sh
node docs/product/fractalmind-app-prototype-v2/verify.cjs
```

覆盖达成度计算、完成与验收、草稿质量校验、ACTIVE 上限与归档、完整的 heartbeat 剧情、预算与约定版本、
审批与权限、取消与重试、路况注入、主机命令与改派、邀请码（证明绑定、并发、失败与结果未知）、设备授权、
恢复码、运行费、对话方案失效、Agent 发现与交接、组织隔离与导出，以及演示数据引用完整性和页面只加载本地文件。
`.github/workflows/prototype.yml` 在原型目录变化时运行它；浏览器交互走查仍需单独进行。
