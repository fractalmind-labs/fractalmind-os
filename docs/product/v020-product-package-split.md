## 核心授权边界

- 扩展类型的原始包来源由组织授权注册。direct 与 OKR 分属固定 family；替换已注册来源被拒绝。
- 扩展私有构造的 `Witness` 经 core 检查来源、能力绑定及组织权限后，才能获得不可持久化的执行见证、写入许可范围内的加密产品记录或执行已审阅接管。
- 组织和能力的扩展字段采用带 Witness 类型参数的独立键；桥没有公开任意组织 UID 或未校验写入接口。core 继续维护共享工作区占用，使不同实例的 direct 写入受到 OKR 写保护。
- SDK／App 配置区分 core、OKR、direct 的调用包和原始类型包。envd 区分 core 和 OKR，分块密文 helper 仍路由 core。直接消息运行时尚未接入。
- 从 main 已有源码保留既有模块及结构；本次移动的是尚未发布到 main 的产品 OKR/handover/direct 模块。**没有验证已发布 main 的真实原地升级、混合类型来源或旧开发单包对象迁移**。

后续[main 原包升级增量](v020-main-upgrade.md)已在新的隔离 localnet 部署验证真实兼容升级、原组织迁移以及 SDK 混合类型来源；本报告的原证明范围保持不变。App／envd 完整升级执行、公共部署升级及旧开发单包历史迁移仍未完成。

## 真实执行与直接权限验证

[实际 OS 密钥库＋localnet＋生产 envd](evidence/v020-product-three-package-native-localnet.json)：12 项检查、29 笔 App 确认交易／费用。

1. 原生创建身份与组织，真实 Host 邀请兑换，设备 HTTP 鉴权、签名发现及已有实例导入。
2. 真实 Agent 审阅、原子接管审批、明确投递两个 KR；恢复原票据和原始结果不重复派发。
3. 两个 KR 分别人工验证，最后独立验收，链上状态 ACHIEVED（3）、游标 2、OKR 工具预算 6 已支出／0 预留。Human 决策由隔离脚本明确给出，不能替代安装后人工 UI 验收。
4. OS 加密直接消息、常驻权限及原 Run 绑定；普通 3 次工具预算预留后取消归零。单次 5 次审批原子消费并独立记账，常驻总额仍为 6；权限换版拒绝旧准备请求，原历史取消结清预留，OKR 支出仍为 6。
5. 实际 Host 撤销后路由及心跳被拒绝，授权 Human 仍能读原历史结果；测试 OS 凭据已清理。

直接消息仅验证链上准备、审批、签名与结清，**没有派发 direct.message，也没有正式对话界面**。执行适配器为实际有界文件 Agent，Host 密钥注入隔离内存，原生传输为子进程，技术 journal 为内存。

联测发现并修复：拆包目录缺失判断、实际 gRPC 的标准化框架类型名、原生 direct 签名范围，以及取消确认后对象读取的可见性等待。前序失败没有覆盖：第六轮原取消已确认但读到旧预留 3；只读复查原对象证明 Run 已取消、预算归零和 claim 已结清，没有重发原交易。
