依据 #34/#43/#45、PRD v0.11 与原型 v2；基线 `5990409`。
本增量接通真实生产配置、HTTP 客户端和执行适配器。完整 #40 仍未完成。

## 实际能力

原生 App 的固定实例沟通窗口支持 `ask`：常驻权限明确勾选问答、分别确认消息／能力／Run 的费用与签名，再明确投递原命令。问题工具预算固定为零，不能附带文件任务；不会打开文件句柄、暂停已有 OKR 或取得物理执行槽。Host 只把这条已签名的问题发给自己配置的模型。

Host 执行端在请求模型之前和收到回复之后重查链上权限、当前原 Run、固定实例及期限。回复沿已有加密结果与原 Run 保存；App 展示模型名称及输入／输出 token，并标记为待审阅建议。它不能代表文件观测、执行授权、KR 验证或最终验收。重新打开只读取原结果，不能推断需要再次请求模型。

同一原生文件运行时可让配置的模型选择批准任务的下一次文件读取／写入。模型拿到已批准的具体文件目标、实际 Host 观测和剩余工具额度；没有工具句柄、签名钥或链上写入接口。Host 对每个动作重新检查：

- 原约定、工具目录、预算、当前 Run 和有效期仍成立；
- 文件路径和写入内容匹配已批准的目标，模型不能调整目标或扩大目录；
- 工具执行仍沿现有 `os.Root` 目录句柄、冲突哈希、逐次权限 hook 和实际计数；
- 只有实际读取文件所得的哈希及时间成为测量证据。模型宣称“完成”不能产生证据；
- 达到请求／工具上限、模型失败、提出新目标或收到停止／撤销时结束本次推进。不会转为确定性执行、重试模型或扩大权限。

这是目前 **1–3 个明确文本文件目标** 的工具选择能力；尚不证明从自然语言 OKR 自主生成完整项目方案、修改任意代码或持续自我调整。没有配置模型时，既有明确文件执行路径保持可用，问答返回不支持。

## Host 配置与数据去向

`sentinel.yaml.example` 的 `runtime.model` 默认为关闭；启用时必须选择 `native-file-agent`，明确设置 `api_base` 和模型名称。接口采用 [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages/create)。提供方不获得 Host 工具；不启用远端工具或 shell。

远端端点要求 HTTPS；本机兼容模型可以使用显式 loopback HTTP。禁止端点中的登录信息、查询参数和片段，也不跟随 HTTP 重定向。凭据从指定的进程环境变量读取，不保存到 YAML／Sui，也不放进回执或错误正文。默认每次回复最多 2048 token、请求超时 30 秒，每个 OKR Run 最多 12 次模型请求；可设置的上限分别是 4096 token、300 秒和 32 次，原 Run 期限仍生效。直接问题只有一次模型请求。

启用后，问题文字以及批准文件任务与实际文件观测会发给这个 Host 的提供方。**模型账单与 SUI Gas、TOOL_CALLS 分开**；工具支出为零不表示模型请求免费，超时也不能证明提供方没有收费。token 是提供方回执中的数量，不是已核实的货币账单。App 尚未接通模型配置／鉴权向导、提供方预算审批和撤销；当前需在 Host 明确配置。

当前每个直接问题独立提交，只使用该条已签名的文字，没有自动加载历史对话或整个私有 OKR。多轮上下文、消息转 OKR 草稿和自动 Host 投影同步仍需接通。

## 验证与局限

[R2 实际 OS＋Sui localnet＋生产 envd](evidence/v020-host-model-localnet.json)：**17 项检查、54 笔 App 确认交易**。合成接口被调用七次：六次选择两个 KR 的工具动作，一次回复正式 App 的零工具问题。两 KR 各有独立人工验证，再单独最终验收；工具预算 **6 已用／0 预留**。直接问题的原 Run 与加密回执在空技术 journal 的控制器中重建，没有第二次派发／模型调用；常驻 **4 已用／0 预留**、单次审批 **6 已用／0 预留**，问答没有改变工具账本。

[最终回归](evidence/v020-host-model-unit.json)：App **216/216**、构建及联测脚本严格类型通过；Go 模型接口、工具、运行时、命令、Coordinator、WebSocket、envd 七包 race 通过。模型无工具、错误／重定向无重试、初始观测 wire、改目标／假完成拒绝、并发 OKR 问答、原请求不可替换、停止与目录变更后的旧回复拒绝均有专项。R2 正向联测之后新增的问答停止／目录保护由最终 Go 测试验证，未将正向联测称为实际运行中停止的实机证据。

[真实网页检查](evidence/v020-host-model-browser.json)核对中文白天／英文黑夜及原生保护；没有注入桥、读取加密消息或广播。它没有验证解锁后的问答选择器、费用、签名与回复完整 UI 旅程。

本轮的实际模型凭据未配置。联测通过显式 `--model-fixture` 启动 **合成 loopback HTTP 接口**：它输出固定回复或根据实际观测选择固定的工具请求。链、OS 密钥库、envd、文件工具及加密回执为真实生产路径；提供方的回复不来自真实语言模型。此证据只能验证接口、权限与原记录，不能证明真实模型兼容性、质量或计费。

[原 R1 与只读复查](evidence/v020-host-model-prior.json)在第一条 KR 后等待成功状态超时；原 Run 确认状态为失败、有原加密结果，工具预算 **0 已用／0 预留**，OS 测试凭据清理确认。没有重放。发现初始观测列表被序列化为 `null`，联测夹具要求数组；修正为 `[]` 并补充 wire 检查。原失败回执已在身份清理之后，只读复查不能解密原失败正文，因此不把这一处序列化问题当作已核实的唯一失败原因。
