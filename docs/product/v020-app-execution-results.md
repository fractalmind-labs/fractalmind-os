# App 原执行结果与 Host 审阅读取

依据 PRD v0.11／原型 v2，承接[原生命令结果密钥](v020-app-command-results.md)。本增量将原 Run 的链上结果读取接入正式 App，并提供后续交接控制器所需的 Host 审阅验签方法。

## 读取边界

`NativeExecutionResults.read` 要求本机设备持钥与当前组织 read 授权。核对指定实例的共享 Run、不可变 EncryptedRecord 的 UID／类型／组织、命令指纹、记录版本、原 Human／Grant 及 Host 作者、时间与密文 SHA-256。FME2 同时核对结果密钥授予的组织／成员／Host／版本及封装头；预算预留和结算状态必须对应 Run。

原生系统密钥库按链上设备 keyring 解密。正文释放前重读设备权限与整个 Run，读取期间撤销或状态变化时拒绝释放。正文的版本、命令、操作、实例目标、结果状态及已知工具支出不能与链记录冲突。缺失终态结果是错误；排队／运行／未启动取消没有虚构正文；结果未知仍保持其预留预算。

交易摘要仅来自原不可变结果对象的 `previousTransaction`。正文内的 `transaction_digest` 会被替换，不成为交易证明。读取原结果不以当前记录头替代历史对象，也不重发命令、产生业务缓存或取得执行权。Host 撤销不会删除历史：只要当前设备仍获组织读取授权，可以查看原结果。

`readReview` 另外核验调用方保留的原签名状态命令、提案与 Run 的精确关系，从原成员共享对象核对组织／Host／入口与签名公钥，验证链上结果中的 Host 接受签名，并检查链 Clock 和本机时间下的原审阅有效期。它只证明历史审阅，**不能授权接管**。完整审批仍须核验当前成员／入口、实例及规格版本、完整零未结执行目录、物理预约与当前权限，并取得明确费用确认。此方法尚未接入完整交接 UI。

## 界面

v2“团队与 Agents → 检查旧执行 → 执行记录”新增原执行结果读取。原生 App 选择设备配置／授权后，逐条重新核验并读取；正文在页面内存，60 秒或切到后台隐藏，配置／授权切换、重新检查及卸载使旧异步读取失效。结果正文优先展示，技术字段可展开查看；状态及原摘要同时保留。结果不等于人工验收或继续授权。

网页仅展示“在桌面 App 中可读取链上加密结果”，不提供原生解密按钮、私钥或恢复码输入。[浏览器检查](evidence/v020-native-execution-results-browser.json)覆盖当前真实链上的 4 条历史、中英文／明暗、网页权限边界和横向布局。安装后新控件、自动隐藏与实际 Tauri IPC 的操作旅程尚未验收。

## 验证证据

- [App 回归与构建记录](evidence/v020-native-execution-results-unit.json)：**109/109** 回归通过，其中新增 6 组覆盖真实 BCS／密码学互操作、18 种来源替换、读取中撤销／Run 变化、正文／状态／预算冲突、未知／取消以及 Host 审阅签名伪造。随后成员／入口／公钥核验补充后，6 组专项与构建再次通过。单元测试设备权限核验器为受控夹具；下方实际链专项使用正式核验器和 OS 密钥库。
- 类型检查、生产构建和联合链脚本严格类型检查通过。SDK／Rust／Go／Move 本增量未修改；既有构建体积和依赖注释警告保留。
- [真实 OS＋localnet 专项](evidence/v020-native-execution-results-localnet.json)：**9 项检查、12 笔确认交易及实际费用**。原生封装与签名准备、独立 Host 解包、链上原 Run 开始／结果发布、正式 App 原生读取、原摘要来源与 Host 撤销后历史读取均通过。原 Run `0x02de420ef0a7a589eb66486ede9fe3df0c685be161563550a4b9266361d13be1`，结果创建摘要 `2KaXb526koat5RdTYAXHqU2Ahov5a92MnGgE4TFxP5qa`。隔离测试凭据已清理。

专项由隔离 Host 夹具签署开始／发布交易，正文明确标记 fixture；**没有 envd 派发、实际物理状态观测或 Human 接管**。原生传输为独立子进程，journal 为内存，不能证明安装后 IPC／重启恢复。Host 审阅验签在单元测试通过，尚未完成 App 与实际 envd 审阅的联合验收。

[第一次终止及原请求只读复查](evidence/v020-native-execution-results-prior.json)完整保留：9 笔成功费用回执，原准备摘要 `93kJh63mq7Zqad3KLQqcMaBFNPP91Hoyg2Eg6PRFCDFC`；随后交易已裁剪，journal 查询返回 unknown，原 Run 仍排队／无结果／无派发，测试凭据已清理。修正 harness 对历史查询必须 confirmed 的假设，原成功回执和查询未知分别保留。第二次是独立夹具，不重放或结清第一次原 Run，也不证明其结果。

复现：在 App 目录对已有隔离部署使用新的报告文件运行：

```sh
node --import tsx scripts/native-command-results-localnet.ts DEPLOYMENT.json NEW_REPORT.json --read-result
```

已有报告／进度文件拒绝覆盖。历史查询不可用不授权重放；结果创建摘要由对象来源恢复。
