# v0.2.0：实例执行目录与接管前检查

依据 PRD v0.11、J11 和 `fractalmind-app-prototype-v2`。本增量完成接管前的链检查，完整接管与 v0.2.0 仍未验收。

## 生产行为

新导入的受管理实例在 Organization 上建立完整执行目录，跨 Capability 与 OKR 记录命令、控制类别、是否结算及目录修订。排队、运行、结果未知的控制命令都占用未结计数；命令到期不会自动释放预算或允许接管。只读命令保留在目录中，但不计入未结控制。

已知终结结果与预算结算在同一交易里清除未结计数。排队取消原子释放预留预算，支出为零；运行中请求停止只设置停止请求，等待 Host 的已知终结结果。`rebind_agent`／版本条件入口在修改关联前要求完整覆盖且未结控制为零，分别用 Move `9209`／`9210` 拒绝缺失覆盖／存在未结控制。

目录没有初始化的历史实例视为覆盖未知，不能假定旧执行为空或自动接管。保留原公开入口的参数签名和已发布结构布局；新增 `prepare_agent_command_v2`、`okr::prepare_command_v2` 及对应取消入口处理可变 Organization 和执行目录。旧准备／排队取消入口不能绕过新实例的目录。SDK 使用新入口，不自动退回旧入口；部署必须包含这些函数。历史实例完整覆盖的迁移仍待实现。

本轮实际部署为首次发布。新结构首次在既有包升级中引入时，其 Sui 类型来源可能与原包不同；SDK 当前按配置的 `originalPackageId` 查类型，此类升级的类型来源解析与迁移仍待实现／验证，不能据本轮首次发布测试声称升级部署可用。

SDK 读取完整分页，核对共享对象、精确类型、组织／实例／Host／Capability 绑定、执行状态与预算、目录计数，并在读取后重查实例与目录修订。分页索引落后于对象写入时拒绝返回部分历史；缺失、RPC 失败、快照变化与空目录有区别。

App 的 v2 “团队与 Agents”卡片增加“检查旧执行”：显示读取时间、未结控制数量，展开查看全部执行状态及已花费／预留预算。网络、实例或权限上下文变更会清除检查；检查 60 秒后显示过期。数据仅留在当前页面内存中。零未结仅说明本次链读取的事实，还需当前 Host 物理状态、适配器接受约束和用户明确授权；页面不会自动授予控制或继续任务。

- [前序检查与原摘要](evidence/v020-agent-execution-prior-checks.json)：保留五次独立夹具的已确认交易及结束阶段。前三轮目录读取拒绝索引延迟，第四轮正确预检拒绝后，测试错误地检查了通用异常文本，第五轮取消夹具未授予所需预算而在模拟阶段拒绝。未将它们判为新的广播失败，未重放原交易。第三轮原命令在后续**链 Clock**读取时已到期，仍为排队、预留 6、未结控制 1；未派发文件执行，也未被后续独立组织的成功掩盖。

## 重现

使用本轮部署或包含上述新入口的隔离部署，以及一个不存在的新报告路径：

```sh
FM_ENVD_JOIN_CLI_BIN=/tmp/fm-envd-native-execution-tests \
FM_ENVD_CHAIN_CONNECTION=1 FM_ENVD_AGENT_DISCOVERY=1 \
FM_ENVD_AGENT_IMPORT=1 FM_ENVD_NATIVE_DISCOVERY=1 \
FM_ENVD_NATIVE_EXECUTION=1 FM_ENVD_HOST_REJOIN=0 FM_ENVD_AGENT_REBIND=0 \
node --import tsx scripts/host-admission-localnet.ts DEPLOYMENT.json NEW_REPORT.json
```

命令在 `apps/fractalmind-app` 执行；Go 测试辅助二进制的构建见[原生执行说明](v020-native-agent-execution.md)。夹具使用新生成的内存钥及注入 App 传输；控制标签通过 raw SDK 显式设置，不是 App 安全交接。目录索引可见性只重查原实例的链数据，不重放写交易。

仍需完成 Host 约束确认、旧执行安全结束／未知结果处理、OKR 授权和用户明确继续的完整 App 流程，以及直接沟通／人验收、真实云 Host、OS 密钥库与五平台安装运行。完整目标保持不变。
