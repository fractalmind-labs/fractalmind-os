# v0.2.0：提前授权后续 KR 与链上原状态恢复

依据 [#34](https://github.com/fractalmind-labs/fractalmind-os/issues/34)、#33/#37/#28、PRD v0.11 与原型 v2；基线 `2b2c9aa`。本增量接通已批准固定计划的后续 KR 准备与 Host 顺序执行，完整 [#40](https://github.com/fractalmind-labs/fractalmind-os/issues/40) 仍未完成。

## 用户流程

工作台「执行与继续」在读取已批准私有计划后提供「提前授权后续 KR」。用户审阅后续文件目标、范围和逐 KR 工具上限，逐笔确认权限、命令准备及链上投递费用。每条 KR 使用独立的原签名命令、Run、结果密钥及不可替换的投递密文，全部预算预留计入原 OKR 总上限。

后续 KR 可以先发布到 Host 队列。Host 开启 `runtime.chain_queue` 后独立读取 Sui；未来 KR 保持排队，直到前一 KR 经 Human 独立验证、链上游标推进后才执行。执行顺序、实际工具检查、结果与测量仍沿原生产 Executor 和合约；Host 不取得 Human／组织管理员权限，不签发新能力或新 Run，不替 Human 验证或最终验收。

当前 KR 的明确投递保持原入口。提前授权流程只处理剩余 KR，按最后一条到最近一条准备，每笔费用须明确确认；取消或结果未知即停止后续提交，保留已准备的原状态。重新进入时从原票据定位同一 Run，不能用新 nonce 替代一个未知请求。关闭 App 不撤销已发布命令；撤销、暂停或停止仍须使用原介入流程。

**命令最长有效期仍为 5 分钟。** 本增量是有限、固定计划的预先授权，不代表长时间无人值守、Host 自动续签、通用模型规划或持续创建新任务已完成。每条 KR 的 Human 验证仍是独立门槛；超时的原预留须按原停止／结算流程处理后再授权。

## 协议与权限

- Move 增加显式 `prepare_scheduled_command_v2`，允许当前约定中尚未完成的具体 KR 预留；普通准备接口仍要求当前 KR。begin／observe／verify 的原顺序约束保持，提前准备不能提前开始执行或推进游标。
- 原 Human、DeviceGrant、组织、Host 成员资格、固定实例及版本、约定／边界、能力、结果密钥、全局预算和期限检查继续生效。结构布局没有在此增量中增加字段；本次验证是新部署，不能据此声称旧包升级通过。
- SDK 的 `scheduledKrIndex` 只用于显式 `prepareOnly`，禁止同时投递；规划阶段投影指定 KR，签名前后继续核对真实链上游标。并发调用只合并相同原操作，不把另一 KR 的请求并入当前请求。
- App 提前授权只允许同一当前约定的原预留共存；其他 OKR、直接控制或未知 Run 仍阻止新授权。Human 当前 KR 验证只允许严格未来、同约定、同实例、同边界的排队预留，并核对其总额等于链上未结算预算。最终验收仍要求预留为零。
- Host 先核对当前约定、游标、成员／实例与测量状态；未来 KR 的等待是只读，不产生执行尝试或重试。合约 begin 与逐工具权限 hook 继续强制执行约束。

## 恢复与历史回执

原交易历史与当前产品状态分别查询。节点裁剪历史后，原 digest 的交易查询可能返回 `NOT_FOUND`；管理器保留 `unknown`，不以本地缓存的 `confirmed` 代替链上回执，也不据此补发。

新增 `readPreparedKr` 从当前约定读取精确加密票据，核对原签名、目标文件／范围／工具上限、原 Run 字段、同 KR 的预算 claim 和不可变投递记录。这个读取不报价、不签名、不广播或派发；当前约定改变时拒绝把旧票据当作新授权。

工作台重新读取计划会重建已存在的原 Run／投递列表，查询时分别显示「原交易回执暂不可读」和「链上原 Run 当前状态／命令是否发布」。未发现投递记录也不构成重发许可。交易实际费用只有原回执可读时才由回执证明；当前 Run 存在或执行成功不能补出历史 Gas 账单。

- [回归](evidence/v020-scheduled-okr-delivery-unit.json)：App **218/218**、SDK **158/158**、OKR Move **13/13**（含五个提前准备场景）、Go 三包 race、App／SDK 构建与严格类型通过。Move 负例覆盖普通接口不能提前准备、不存在的 KR、总预算超限及 Host 不能提前开始；单位测试使用明确 test-only 接入夹具，真实接入由 R3 单独验证。未重复声称当前增量重跑了 unchanged core/direct Move 或 Rust。

## 尚未完成

R3 的 Human 密钥使用实际 OS 测试密钥库；Host 密钥与技术 journal 为隔离内存，决定由脚本明确给出，Coordinator 在本地回环运行。关闭的是原执行控制器，**没有实际关闭 App 窗口、锁定 OS 密钥库或重启物理 Host**。
