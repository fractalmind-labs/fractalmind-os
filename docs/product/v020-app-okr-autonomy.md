# v0.2.0 App：受约束的单 Agent 持续推进

依据 #34/#27/#28/#30/#33、PRD v0.11 与原型 v2。基线 `c6b6e16`。
本增量接通已批准文件计划的连续执行会话；完整 #40 保持未完成。

## 用户操作

工作台「持续推进」读取已批准目标、成功标准、当前 KR、具体文件计划、工具预算及版本。用户确认本次 Gas 总上限和 1–60 分钟时长后，原生 App 自动准备、签名和投递当前 KR。

KR 有测量及原证据后，循环等待独立 Human 验证。验证推进链上游标后，同一个会话自动准备下一个 KR。所有 KR 验证完成后，循环结束并等待另外一次最终人工验收。此控制器没有验证或验收接口。

每次 heartbeat 只推进同一份已批准约定；相同 heartbeat 合并。界面显示当前 KR／原 Run、状态／依据、最后核对时间、本次已承诺 Gas 上限和交易摘要／实际费用。费用按每笔能力／执行准备交易的最大 Gas 预算保守累计；人工验证和最终验收分别确认费用，不计入自动会话上限。

关闭工作台、切换关注目标、进入后台、到期或明确结束自动推进时，停止后续自动操作并释放私有计划。本次授权是解锁期间的临时会话，重开不自动恢复执行。已经开始的 Run 须通过「暂停与调整」请求停止并核对实际结算；结束本地循环不代表链上执行已取消。

## 权限与原执行

- 原生设备的当前 Human、代次、grant、组织角色、Host 成员、受管理实例、工作区及 Coordinator 绑定持续核验。权限／绑定／约定变化、撤销、期限或预算不满足时停止推进。
- 身份验证器保留每次操作内部的严格对象版本检查。跨正常产品写入的会话使用独立的 `authorityContextPin`，固定实际权限字段、grant 正文及组织角色；组织对象因保存记录而正常换版不会伪装为权限变化。
- 单次能力、预算（含在途预留）、原 Run、加密票据与证据均走已有正式 SDK／Coordinator／envd 路径。没有新增执行引擎，Host 每次工具前仍强制校验边界。
- 恢复或查询出的原排队／未知执行不会自动投递。只投递该会话刚创建、已经确认的精确票据与 Run；未知费用或结果停止循环，先查询原请求。
- 投递前原子保存公开技术标记，写入失败、重复或关闭后都不能投递。共享 IndexedDB 标记覆盖手动继续和自动继续入口；它不包含私有正文、签名或密钥。失去缓存也不能令恢复出的原 Run 获得自动投递资格。
- SDK 的继续操作可固定原 Run、约定版本和 KR，异步确认后不能释放另一条执行。没有原票据时也不能创建替代 Run 来满足旧执行定位。

| 一次会话确认 | 固定两 KR 已批准文件计划，Gas 上限 800000000 MIST |
| 两个 KR | 自动准备及投递，实际投递 2 次，能力／票据报价各 2 次 |

## 前序原事实与限制

[R1 原失败及只读复查](evidence/v020-okr-autonomy-prior.json)：原能力和票据交易确认后，正常 Organization 对象换版触发了错误的会话权限判断，因此投递前停止。原 Run 保持排队、工具已用 0／预留 3，没有工具结果；OS 凭据清理不等于链上取消或撤销。R2 使用新隔离组织，没有重放 R1 原请求，也没有把新成功当作旧预留已释放。

R2 的 Human 决定由明确脚本提供；原生桥为实际 OS 密钥库的隔离子进程，Host 密钥、技术 journal 及投递标记采用内存测试实现，Coordinator 为同机 loopback。实际安装后的 Tauri IPC／IndexedDB 正向旅程、公开回执界面及标记故障分支仍需验收。R2 后追加的缺失原 Run 拒绝与 IndexedDB 阻塞处理由最终单元／类型／构建覆盖，没有伪称安装界面已经验证。

当前计划适配器仍只执行明确文件目标。**尚需完成**：技能规划与链上投影、通用模型对话、无人值守 Host 持续循环、运行中工具停止确认、首次直接安全纳管、安装后 UI 全旅程、真实云 TLS Host、手机核心旅程、彻底清缓存重启恢复与 main 旧包升级。不会以此次文件循环关闭完整 #34/#40。
