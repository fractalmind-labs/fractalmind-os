# FractalMind v0.2.0 OKR 投影契约

本契约用于启用 Sui 组织的 Agent OS workspace；独立文件模式仍可使用原有契约。`OKR.md` 只投影 ACTIVE，最多三条；暂停、草稿及历史可在客户端查看，不通过移出文件改变链上生命周期。

## 来源与未提交修改

每个投影包含网络、原始协议包、组织、OKR 和规格记录 ID、规格修订、业务版本、约定版本与本次链上读取时间。ID 使用完整 Sui ID，u64 数值使用十进制字符串。业务版本不能代替约定版本；读取时间不能代替指标采样时间。

保持链上来源元数据，局部修改明确标为 `UNSUBMITTED`，不得将这些修改显示成已签名或已生效。提交时由具备权限的设备重新读链、检查版本，明确签名；等待确认期间保留提案。结果未知时查询原交易，不自动重发。确认后重新投影。客户端尚无提交接口时保留未提交状态，不能借脚本自动授权。

规格修改仅在 DRAFT/PAUSED 进行；修改会清空当前指标与验证并改变约定版本。重新执行须重新审批。旧正文、Run 和观测历史仍可从链上读取，不能覆盖为新版本的证据。

## 指标与执行约定

- 一个负责人 Agent，1–3 个顺序 KR；KR 编号从 0 开始，对应链上 `next_kr`。复杂依赖图由后续版本承接。
- 每个 KR 包含结果、产出、基线、目标、当前值、单位、整数精度、提升/降低方向、权重、最大采样年龄、证据方式及采样时间。非负 u64 固定精度与链上类型化指标一致；降低型基线大于目标，基线不得等于目标。
- 未采样、未来或过期采样表示未知；不能填 0 冒充实测。展示最近观测及新鲜度，不凭心跳频率推断目标进展。
- 来源 Run、证据记录、约定版本与验证记录分开保存。观测、KR 已验证、整体已验收分别表达；指标 100% 或 Run 成功不能自行达成 Objective。
- 约定投影包含受管理实例与成员版本、工作区/边界摘要、允许动作/路径、预算资产、上限、已支出、在途预留及期限。文字范围不能扩大实际执行端权限；支出加预留参与预算检查，未知结果保留预留。
- 验证与最终验收经授权设备完成。文件更改与 Agent 自报不能替代这两个链上操作。

## 心跳观测

`HEARTBEAT.md` 的当前执行面引用相同 OKR、约定版本及 KR。每次报告包含：观测时间、来源 Run/证据、指标值或未知原因、步骤及下一步、阻塞原因与开始时间、最后确认预算及其读取时间。对状态的解释附依据，不把推断当实测。

心跳文本不自动成为已提交观测、持久检查点或执行授权。涉及持久状态的变化继续走现有链上写入及签名流程；原始运行时观测须经 Host 身份和当前成员资格校验。重新连接或恢复须重新读取授权、约定、停止状态和账本，不根据旧文件重复执行。

可移植的英文示例见 [技能投影示例](../../../../skills/coordination/okr-manager-skill/examples/sui-projection.md)。这是字段及行为契约；客户端导出、草稿导入和签名提交仍需按 #39/#37/#38 集成验收。
